Under the hood

Six subsystems, each testable alone.

CATALOG

Runtime schema discovery

The channel list is read from the binary telemetry header at runtime — nothing hard-coded — so it's complete for any car or content, with types, units and bitfield decode tables.

GET /variables
INGEST

Live and offline

One pipeline reads the iRacing shared-memory feed at 60 Hz and parses recorded .ibt files in tick-window chunks, with async import jobs and status polling.

shared-mem · .ibt
STORE

Columnar, pruned per lap

Metadata in DuckDB; high-rate telemetry as per-session/per-lap Parquet. Every chart query prunes to one or two small files instead of scanning a session.

DuckDB + Parquet
STREAM

Backpressure-safe live

/ws/live delivers latest-frame-only at each client's requested rate. Slow clients coalesce to the newest sample — no unbounded buffering, no lag spiral.

WebSocket fan-out
FRONTEND

MoTeC-i2 analysis UI

Canvas charts, GPS track maps, histograms, suspension and a live Pitwall console — plus alien-lap cross-session compare to set another driver's lap as your reference.

time / distance worksheets
COACHING

1M points → 20 findings

Deterministic feature extraction aligns main and reference laps, detects corners, and apportions a time-delta curve to eight diagnostics before any LLM sees the data.

GET /coaching/lap-findings

The AI race engineer

Four layers. The LLM never sees raw telemetry.

Heuristics find brake points and speed deltas faster and more reliably than any model — so they stay deterministic, and Claude is used only where code is weak: synthesis, prioritisation, and open-ended Q&A. That same deterministic layer becomes the eval ground truth — so the graph coach can refuse a question the data can't answer and every figure it does state is checked against the findings, in-loop.

1

Deterministic features

Aligns laps on a uniform distance grid, detects corners as speed minima, builds a time-delta curve and runs eight diagnostics into a compact LapFindings model. This is the token solution and the ground truth.

free · code

MCP server

Six tools over the API — get_lap_findings, compare_channel, get_corner_detail and more — driven from Claude Desktop / Code. "Review my lap 5 vs my fastest."

$0 · subscription
3a

Multi-agent orchestration

Fan-out a specialist per priority corner → synthesise a session plan → adversarially verify it, all in structured Pydantic outputs with a cached findings block.

~cents · Claude API
3b

LangGraph coach + eval flywheel

A model-driven agent → tools → validate → refuse graph over the same findings. It refuses questions the telemetry can't answer — citing the channels that are captured, never an invented number — and validates every figure in-loop against ground truth, bouncing a claim the findings don't support. A hermetic harness replays these behaviours with baseline-diff regression — offline, no key.

~cents · Claude API
